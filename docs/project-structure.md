## 3. Multi-tenancy / Data Isolation

### Approach

Single-database multi-tenancy via **`subscription_id` column** on the `Subscription` model. Each subscription is a tenant (a business/client). All data is scoped to a subscription, either directly (via `subscription_id` column) or transitively (via `branch_id` → `branch.subscription_id`).

There is **no** package like stancl/tenancy. Scoping is manual through Middleware and a Trait.

### How it works

#### 1. `HasSubscription` trait (`app/Traits/HasSubscription.php`)

Provides `getSubscriptionId()` and a `scopeBySubscription()` scope. Models that use this trait can resolve their subscription through:

- Direct `subscription_id` column, OR
- A `branch()` BelongsTo relationship → `branch.subscription_id`

```php
trait HasSubscription
{
    public function getSubscriptionId(): ?int
    {
        if (array_key_exists('subscription_id', $this->attributes) && $this->attributes['subscription_id'] !== null) {
            return (int) $this->attributes['subscription_id'];
        }

        if (method_exists($this, 'branch')) {
            $branchRelation = $this->branch();
            if ($branchRelation instanceof BelongsTo) {
                $branch = $this->relationLoaded('branch')
                    ? $this->branch
                    : $branchRelation->getResults();
                if ($branch && isset($branch->subscription_id)) {
                    return (int) $branch->subscription_id;
                }
            }
        }

        return null;
    }

    public function scopeBySubscription($query, int $subscriptionId)
    {
        if (in_array('subscription_id', $this->getFillable()) || array_key_exists('subscription_id', $this->attributes)) {
            return $query->where('subscription_id', $subscriptionId);
        }
        if (in_array('branch_id', $this->getFillable()) || array_key_exists('branch_id', $this->attributes)) {
            return $query->whereHas('branch', fn($q) => $q->where('subscription_id', $subscriptionId));
        }
        return $query;
    }
}
```

Models using `HasSubscription`: `Branch`, `Product`, `Customer`, `Transaction`, `Expense`, `ServiceOrder`, `CashRegister`, `CashRegisterSession`, `PrintTemplate`, etc.

#### 2. `EnsureSubscriptionScope` middleware

Registered globally for web routes in `bootstrap/app.php`:

```php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->web(append: [
        \App\Http\Middleware\EnsureSubscriptionScope::class,
        // ...
    ]);
})
```

#### 3. How "current tenant" is resolved

The `Subscription` is the root entity. A `User` belongs to a `Branch`, which belongs to a `Subscription`. All queries filter by `branch_id` (which is scoped to the user's branch), and through the branch, data is implicitly scoped to the subscription.

```php
// In controllers — typical pattern:
$user = Auth::user();
$branchId = $user->branch_id;

$query = ServiceOrder::query()
    ->where('branch_id', $branchId)
    ->with('branch:id,name', 'transaction.payments');
```

The `Subscription` model itself stores the tenant identity (`business_name`, `slug`, `status`).

## 4. Service/Action Layer Pattern

### Action class example — `CreateServiceOrderAction`

```php
namespace App\Actions\ServiceOrders;

class CreateServiceOrderAction
{
    use OptimizeMediaLocal;

    public function execute(array $data, User $user, ?array $evidenceImages = []): ServiceOrder
    {
        return DB::transaction(function () use ($data, $user, $evidenceImages) {
            $customer = $this->resolveCustomer($data, $user);

            $serviceOrder = ServiceOrder::create(array_merge($data, [
                'folio' => ServiceOrder::generateFolio($user->branch_id),
                'user_id' => $user->id,
                'branch_id' => $user->branch_id,
                'received_at' => now(),
                'customer_id' => $customer?->id,
                'status' => ServiceOrderStatus::PENDING,
            ]));

            $transaction = $serviceOrder->transaction()->create([
                'folio' => $this->generateTransactionFolio($user->branch_id),
                'customer_id' => $customer?->id,
                'branch_id' => $user->branch_id,
                'user_id' => $user->id,
                'subtotal' => $serviceOrder->subtotal,
                'total_discount' => $serviceOrder->discount_amount,
                'channel' => TransactionChannel::SERVICE_ORDER,
                'status' => $serviceOrder->final_total > 0 ? TransactionStatus::PENDING : TransactionStatus::COMPLETED,
            ]);

            if ($customer && $serviceOrder->final_total > 0) {
                $customer->addDebt(
                    amount: $serviceOrder->final_total,
                    debtType: CustomerBalanceMovementType::CREDIT_SALE,
                    transactionId: $transaction->id,
                    notes: "Cargo por Orden de Servicio #{$serviceOrder->folio}"
                );
            }

            $serviceOrder->addItemsWithStock($data['items'] ?? [], $user);
            // ... evidence images handled here ...
            return $serviceOrder;
        });
    }
}
```

```php
namespace App\Exports;

class ProductsExport implements FromArray, WithHeadings, ShouldAutoSize
{
    public function array(): array
    {
        $subscriptionId = Auth::user()->branch->subscription_id;
        $branchIds = Branch::where('subscription_id', $subscriptionId)->pluck('id');

        $products = Product::whereHas('branch.subscription', function ($query) use ($subscriptionId) {
            $query->where('id', $subscriptionId);
        })->whereNull('global_product_id')->with(['category', 'brand'])->get();

        // Pre-load stock aggregates from branch_product pivot
        $productStocks = DB::table('branch_product')
            ->whereIn('branch_id', $branchIds)
            ->whereIn('product_id', $products->pluck('id'))
            ->select('product_id', DB::raw('SUM(current_stock) as total_stock'))
            ->groupBy('product_id')->get()->keyBy('product_id');

        // ... builds array rows with product data + stock info
    }
}
```

### Real multi-sheet export — `FinancialReportExport`

```php
class FinancialReportExport implements WithMultipleSheets
{
    public function sheets(): array
    {
        $sheets = [];
        $sheets[] = new SummarySheet($this->branchId, $this->startDate, $this->endDate);
        $sheets[] = new PaymentsSheet($this->branchId, $this->startDate, $this->endDate);
        // Sales sheet per channel (dynamic)
        $channelsInPeriod = Transaction::where('branch_id', $this->branchId)
            ->whereBetween('created_at', [$this->startDate, $this->endDate])
            ->select('channel')->distinct()->pluck('channel');
        foreach ($channelsInPeriod as $channel) {
            $sheets[] = new SalesSheet($this->branchId, $this->startDate, $this->endDate, $channel);
        }
        $sheets[] = new ExpensesSheet($this->branchId, $this->startDate, $this->endDate);
        return $sheets;
    }
}
```

## 11. Config & Secrets

### Per-tenant API keys / settings

**Mercado Pago credentials** for the online store are stored directly on the `StoreConfig` model:

```php
// app/Models/StoreConfig.php
protected $fillable = [
    // ...
    'mp_access_token',
    'mp_refresh_token',
    'mp_user_id',
    'mp_public_key',
    'mp_token_expires_at',
    'payment_mp_enabled',
    // ...
];

protected $hidden = [
    'mp_access_token',
    'mp_refresh_token',
];
```

These are per-subscription (one `StoreConfig` per `subscription_id`), stored as plain columns in the `store_configs` table, hidden from JSON serialization. They are set via the OAuth flow in `MercadoPagoService`.

### Generic settings system

The project has a polymorphic settings system via two tables:

- **`setting_definitions`** (`App\Models\SettingDefinition`) — defines available settings (key, name, description, module, level, type, default_value)
- **`setting_values`** (`App\Models\SettingValue`) — stores the actual value per entity, using a polymorphic relationship (`settable_type`, `settable_id`)

```php
class SettingValue extends Model
{
    protected $table = 'setting_values';

    protected $fillable = ['setting_definition_id', 'settable_id', 'settable_type', 'value'];

    public function definition(): BelongsTo
    {
        return $this->belongsTo(SettingDefinition::class, 'setting_definition_id');
    }

    public function configurable(): MorphTo
    {
        return $this->morphTo('configurable', 'settable_type', 'settable_id');
    }
}
```

Usage: `$branch->settings()` returns all `SettingValue` records for that branch (`morphMany`). This allows per-branch (sub-tenant) configuration without hardcoding columns.

### Environment-based config

Standard Laravel `.env` pattern for non-tenant-specific secrets:

```php
// config/services.php (inferred)
'mercadopago' => [
    'client_id' => env('MP_CLIENT_ID'),
    'client_secret' => env('MP_CLIENT_SECRET'),
    'redirect_uri' => env('MP_REDIRECT_URI'),
],
```

### Current state of per-tenant encryption

The `mp_access_token` and `mp_refresh_token` are hidden from JSON serialization but **not encrypted** at the database level. They are stored as plain text in `store_configs` columns, protected only by field-level `$hidden` on the model.
